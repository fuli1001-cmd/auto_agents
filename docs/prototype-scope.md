# 迭代原型的修改范围与验证

迭代以本轮接收需求时的不可变 Git 快照为起点，并核对真实审批锁、当前需求、前端实现、测试和历史原型。较新的原型不自动成为完整的行为依据；已退役的功能也不因存在于历史文件中就自动恢复。

## 修改范围

控制器将范围分为 `create`、`reuse`、`incremental` 和有明确用户授权的 `redesign`。每个变化都需要当前需求、实际来源证据、具体 HTML 区域和精确文件路径。必要关联改动还需要直接的因果依赖；局部任务不能用整页容器或通配选择器授权。删除和整体重设计需要引用用户目标或已记录决定中的明确授权原文，再由独立审查判断其含义。

默认保留已有功能、选项、默认值、操作流程、字体、颜色及布局。自然布局位移也要声明具体元素、坐标或尺寸属性和引起位移的需求；坐标豁免不能豁免颜色、字体等外观。作用于公共脚本或样式的修改仍须通过未改区域和既有流程回归。

原有 manifest 的视口覆盖必须保留，候选不能自行减少检查视口。明确删除整页时，允许 `remove` 项声明 `whole_page:true`，但授权原文必须指明该已存在页面；局部删除不能被解释为全站重设计。重设计也必须保留未涉及页面的外观和所有未退役功能。

已有原型遗漏而实现或有效需求仍保留的功能，作为基线补全单列。原始基线必须在相应冻结检查上失败，修复副本必须通过，且独立审查必须确认不是恢复已退役功能或覆盖用户改动。结构性补全可以使用 `package-structure`，要求原始 manifest 确实无效，补全后的 manifest 有效。意图冲突或范围扩张通过已有 `answer` 流程处理。

基线补全也受范围保护：`repairs` 可声明 `regions`、`files` 和必要的 `geometry`；省略时，控制器仅从对应保留检查的稳定选择器和页面推导。控制器核对原始与修复后界面在这些范围外保持一致，未声明的文件保持原字节，不能通过补全旧功能夹带全页改色、换字体或提前实现新需求。

## 执行与证据

流程为：

```text
prototype_prepare → prototype_scope_review → prototype
                  → prototype_verify → prototype_review → 人工审批
```

准备阶段只能写基线修复副本。范围审查先运行基线浏览器检查，再独立审查保留流程清单、允许区域、需求映射和断言强度。通过后，控制器把基线字节、范围、检查、输入摘要、用户决定及审查回执存成带摘要的版本化记录。生成阶段不能修改这些记录，写权限仅限候选包和私有临时工具目录。新项目的设计目录选择也在准备阶段冻结；迭代保留已有设计来源。

浏览器检查采用控制器执行的声明式操作和断言。支持点击、输入、选择、勾选、按键、定位媒体时间，以及文本、值、选中状态、可见性、可用性、数量、属性和媒体时间断言。不执行模型提供的任意 JavaScript、测试命令或“通过”报告。每个流程必须映射到非空检查；新行为和保留行为分别检查。

控制器使用本机 Chrome/Chromium 的调试管道，不需要额外 Python 浏览器依赖，也不需要用户指定端口。仅服务候选包的文件；浏览器不连接产品服务、生产数据或付费供应商。每个冻结视口都会执行检查并保存截图，自动比较保留区域的 DOM、默认值、关键样式、伪元素和未豁免的几何属性。未声明修改的文件逐字节保留。截图供独立视觉审查使用，不能替代行为断言。

两版使用同一冻结时钟和随机种子，每个用例从干净的浏览器存储开始，避免时间戳、随机 ID 或上一用例状态造成无关差异。模型接收摘要、文件哈希和只读路径；图片字节和完整 DOM 报告保存在控制器侧，不全部塞进提示中。独立审查可以查看实际基线、候选、完整报告及截图。

候选证书绑定范围、候选包、冻结输入、浏览器回执、截图摘要和独立结果审查。到人工审批时再次核对，文件被改、证据缺失或证书失效均不能批准。manifest 的路径在候选复制为正式原型时作结构化重定位，HTML/脚本字节不能因此被悄悄改写。

没有界面改动且基线有效时，`reuse` 直接使用基线，仍执行验证和独立审查。验证或审查失败最多进行两次范围内修复；缺少浏览器或其他环境失败不会被算作通过。新的审查和修复调用使用原有预算，不增加上限。检查清单是否完整仍需独立语义审查和最终人工审阅，自动断言无法单独证明完整性。

## 恢复、拒绝与预览

拒绝时可通过 `--reason` 记录具体原因；恢复会话会重新核对范围，继续使用最初的不可变来源，拒绝的候选不会成为新基线。已经确认的生产者回执、调用次数和合同保留。

旧 schema-2 会话的未审批原型在恢复时补做新流程，原生产者不会因升级而被重复调用；旧候选通过新检查后才可重新审批，失败后才进行有界修复。内核与监督程序共同协商 `prototype_scope_v1`，原业务合同和回执不重写。

备选原型继承冻结范围和检查，每个候选都要通过验证与独立审查。暂停的备选仍挂在原会话的拥有关系中，输入请求可从原会话查看和恢复。整轮拒绝会取消仍在等待的备选，但保留其操作记录。

重新冻结不能弱化已经通过的保留行为检查：原操作序列与断言保留，可以增加断言和视口。备选继承原范围的全部行为检查；在 `reuse` 基线上请求新设计时，会先准备并审查新的范围，再生成候选。

暂停日志显示范围摘要、基线补全、查看命令、批准命令及带拒绝原因的拒绝命令。预览画廊可以并排比较历史原型、原始基线、补全后的基线和当前候选。端口自动选择；退出预览后再审批。

```bash
auto-agents prototype preview --project /path/to/project --session SESSION
auto-agents reject --project /path/to/project --session SESSION --gate prototype --reason '保留智能时长和原有创建流程；仅增加恢复入口'
auto-agents run --project /path/to/project --session SESSION --auto-approve
```
