- 清除已生成验证镜像的 rootfs 构建目录，回收约 1.35 GiB；WSL 文件系统合计回收约 **8.43 GiB**。另移除了一个废弃验证镜像标签/镜像，不计入上述 WSL 回收数。

清理逐项记录和源码备份保存在主工作区 `.auto-agents/maintenance/`。没有删除旧 job 的冻结快照：这些路径属于恢复证据，并受完整性校验保护。没有关闭 WSL 或对正在使用的虚拟磁盘做离线压缩。

## 已实现的防护

通用诊断快照路径：

- 拷贝开始前检查空间，拷贝过程中每 64 MiB 或每秒复查，并保留至少 2 GiB 的恢复空间。
- WSL 下同时检查当前发行版和 Docker 注册的 Windows 宿主盘；无法确认宿主位置时明确停止，不把 Linux 空闲空间当作完整判断。
- 跳过 Git 确认忽略且没有任何已跟踪文件的 `.next` 构建目录；保留已跟踪文件及其未提交修改。

尚未启用为默认引擎的 V2 分支：

- 只导入当前 provider 必需配置/认证文件，不递归复制 profiles 或历史；保留本次会话和刷新后的认证状态。
- Antigravity 无扩展名认证文件纳入导入；Copilot 的 JSONC 配置正确解析。
- 测试工作副本在成功、失败及异常退出时清理；日志和结构化结果单独保存。容器未确认清除时保留工作副本。
- 带内核租约的崩溃遗留副本，在确认没有使用者和 Docker 挂载后回收；未知旧目录保持原样。
- 镜像内容先计算指纹，已有镜像不重新展开 rootfs；构建目录在结束后清除。
- 命令输出采用有界缓冲和诊断尾部，避免无限保存 stdout。
- 原生 CLI 执行期间定期检查空间；候选导入和冻结前也检查预计复制空间。
- 导入保留候选时保存未提交修改、新文件和删除；验收覆盖不足会写入失败记录；恢复已通过状态前重新校验收据与源码。

这些防护会在空间不足时停止并保留恢复点，不删除有引用的证据来硬凑预算。Linux 内部删除文件也不能被解释为已经释放了同等 Windows 宿主空间。
