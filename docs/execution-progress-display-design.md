# 执行进度与日志显示

日期：2026-09-22。状态：已按实际运行反馈修订并实施。

## 普通输出

```text
[16:08:34] （实现阶段：5/19）task-pp-05：按历史最佳纠正规划并阻断失败下游
[16:08:34]     编码
[16:21:35]     验证
[16:22:24]     审查
[16:25:50]     审查未通过
[16:25:51]     编码 | 最近输出 3 秒前
```

只有最后一条当前动作动态更新。进入下一动作时，上一动作保留开始时间和名称，移除最近输出与进度条。正常通过不新增结果行；失败、阻塞、等待用户和异常退出保留必要提示。

- 标题中的 `5/19` 表示任务在当前计划中的序号，不是已完成任务比例。并行任务分别使用自己的序号；同一任务重试不更换序号、不重复标题。计划改变后以新的计划顺序为准。
- 每个动作开始时记录名称：编码、验证、审查、集成等。去掉尝试次数、provider 名称、服务调用结束、准备下一步等普通日志中的重复信息。
- 非实现阶段按照相同规则显示阶段/动作名称；恢复显示具体恢复步骤。任务标题、回退原因、计划调整和用户问题仍然可见。
- 尚未接收到新的执行动作时，不打印“当前动作未知”等占位状态。
- 最近输出按当前动作、当前任务计算。新动作不沿用上一动作或其他并行任务的输出时间；没有输出时不虚构时间。

## 进度与刷新

验证期间可显示：

```text
[16:21:35]     验证 | [████░░░░░░░░] 1/3 | 最近输出 2 秒前
```

进度按逻辑检查计数，缓存命中也是已经得到的结果；分子包含已返回结果和取消的检查，失败和取消数在发生时单列。不能把进度条视为全部通过的证明。检查结果、每轮尝试等完整信息保存在结构化诊断中。

交互终端每秒原地更新当前动作行，不再每分钟追加心跳。普通文件日志、重定向输出和 `--log-mode plain` 只追加任务标题、动作开始和必要的失败/等待信息，不输出动态后缀或进度条。阶段耗时、本次运行耗时和当前检查耗时不在精简输出中显示。

并行时每个活跃任务保留自己的动作行，并增加任务编号以区分；计数和最近输出互相隔离。窄终端按实际显示宽度截断动态行。显示异常退化到普通文本，当前动作名仍保留。

## 实现边界

- `execution_display.py` 保存展示观察与动作行，生成动作名称、进度条和输出年龄。
- `Reporter` 保留完整结构化事件，并将用户输出转换为标题、动作和失败提示。同一验证轮次的检查失败与任务验证失败只打印一条结果提示。
- `ConsolePresenter` 管理当前动作行的原地显示和历史收尾。动作开始立即写入 `user.log`；终端在动作结束时留下静态名称，不重复写入文件日志。
- provider 输出观察和 `GateObservation` 提供执行输出时间及检查计数，不改动业务执行状态、健康判断或租约。
- 阶段变化、回退、任务新尝试、终态和 owner/lane 交接使旧观察失效。已过期 worker 的结果或输出不覆盖当前动作。
- `events.jsonl` 与 `run.log` 保持完整诊断职责，正常结果的精简显示不影响诊断证据和恢复判断。`debug` 保留完整事件信息。
