# 执行进度与日志显示

日期：2026-09-22。状态：已实施。

## 显示约定

终端上方保留事件日志，下方原地更新进度面板。阶段、任务、动作、尝试次数和验证计数始终对应当前执行观察。以下数字为示例：

```text
[13:41:15] 实现 → 任务验证 | 已完成 3/8 项任务
[13:41:15] T4「规划恢复策略」 · 任务验证 · 第 2 次尝试
[13:41:15] T4 验证进度 7/18，通过 7，失败 0，取消 0
[13:41:15] 当前：检查 8 (tests/test_recovery.py) · 已执行 00:04:18
[13:41:15] 最近输出 12 秒前
```

按用户确认，不显示阶段耗时和本次运行总耗时。

- “实现”是业务阶段，“任务验证”是该阶段中的动作。任务验证可以包含回归测试、验收测试和其他检查，不能将全部验证直接称为回归检查。
- `3/8` 是当前计划中已被引擎确认完成的任务数。worker 完成但尚未集成时仍显示等待集成，不增加完成数。
- `T4` 是任务标识，标题说明处理内容。第 2 次尝试沿用引擎上报的当前动作尝试次数，不计底层网络重连。
- `7/18` 是本轮验证中已经结束并得到结果的逻辑检查数，不是 pytest 测试用例数，也不意味着全部通过。取消数单列，缓存结果属于已得到结果的检查。
- 当前检查显示安全的编号以及可识别的相对测试路径，不显示任意命令参数。当前检查耗时来自真实开始事件；仅有调度事件时显示已提交、等待执行结果，不假装已经执行。
- 最近输出表示最近收到执行输出的时间。终端刷新、普通日志和心跳不更新时间，也不算执行取得成果。
- 缓冲输出的调用显示“当前调用的输出在结束后收集”。没有收到输出时不宣告停滞，也不推断模型在思考。

## 刷新与日志

| 变化 | 进度面板 | 历史日志 |
| --- | --- | --- |
| 检查耗时、距最近输出时间 | 每秒原地更新 | 不每秒新增日志 |
| 阶段、任务、动作切换 | 收到事件后更新，下一次刷新可见 | 立即新增事件 |
| 任务完成、计划调整、重试 | 原地更新完成数、分母和尝试次数 | 立即记录 |
| 普通检查通过 | 更新对应任务的检查计数 | 结构化诊断保留结果，不逐项刷屏 |
| 检查失败、取消、整轮验证结束 | 更新计数，清除已结束检查的计时 | 立即记录具体结果 |
| 60 秒无新可见事件 | 继续每秒刷新 | 输出一次完整上下文心跳 |

`auto` 与 `plain` 共享关键事件语义；`plain` 和重定向输出没有原地面板，只输出事件和心跳。`debug` 继续保留技术细节。

多任务并行显示最多两个任务和两组验证，其余显示数量；每个任务保存独立计数。窄终端按显示单元宽度截断行，清理标题中的换行和控制字符。

## 实现结构

- `execution_display.py`：纯展示数据与文案，保存当前动作、尝试、检查集合、执行输出时间及在途调用。没有业务状态写入、健康判断或租约续期。
- `reporting.py`：复用阶段/任务/计划事件，保留用户日志中的关键变化；动态面板读取同一展示模型。普通模式不再只显示顶层 `status`，验证开始和结束也不再压缩为同一文案。
- `diagnostic_output.py`：可选的开始、收到输出和结束观察回调。观察异常不能中断输出收集，不把原始输出内容交给展示文案。
- `GateObservation`：接收检查开始、调度、结果及结束回调，保存每个任务的验证进度；`gates.py` 在异常路径关闭验证展示。

业务状态与展示动作分开：持久化 `pending` 不覆盖已知活跃动作。终态优先清理活跃展示；明确启动恢复后显示恢复子阶段。阶段变化、回退、任务新尝试和 owner/lane 切换使旧观察失效，迟到的检查结果或输出不覆盖新进度。

展示状态不跨进程伪装存活：恢复时先显示持久化业务阶段和已完成任务数，当前动作未知，收到新的可信执行事件后再显示活跃动作。父子工作流沿用唯一终端所有者和既有 handoff 机制。

事件按主体、阶段轮次、任务动作实例和事件内容去重；心跳不参与普通事件去重。任务完成和计划变更继续以引擎状态为准。

`user.log` 保存关键事件和低频心跳，`events.jsonl` 保留结构化诊断，`run.log` 保持既有执行诊断职责。显示刷新与心跳不写入 `run.log`，不更新健康活动或 provider 租约。

## 验证范围

- `pending` 保存不掩盖活跃阶段/任务，面板刷新不追加日志。
- 任务和动作切换同时更新面板并保留历史；验证结果、失败、取消各自可见。
- fake clock 验证每秒刷新、每分钟心跳、检查耗时和输出年龄。
- 并行任务计数隔离，新尝试、回退、终态和旧 worker 回报不会覆盖当前展示。
- 执行异常结束检查计时，恢复时不虚构活动，缓存和单检查路径能对齐结果。
- 中英文、窄终端、输出脱敏、渲染降级，以及既有健康隔离测试。

已经运行的 Python 进程不会自动加载这些代码；新启动或恢复的进程使用新展示逻辑。
