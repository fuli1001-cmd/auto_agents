# Self-repair V2：统一规划、连续实施、集中验收

V2 是独立修复控制器，不再执行旧的 finding-group / component-plan 调度。`collab`、`fix`、`run` 和原有 provider、session、auto-approve 参数保持兼容。未显式指定修复引擎的 operator 配置默认使用 V2；显式的 `repair_engine=legacy` 仅用于旧版本兼容和对照。

## 一次修复的流程

1. 独立控制进程接管项目锁和原始请求，为当前 job generation 固定控制器代码版本。
2. 冻结目标、验收要求和原会话输入。相同项目/工作流/契约使用同一个持久事务；重启、源版本更新或切换 provider 不刷新未完成修复的预算。
3. 从最新停止的旧候选导入提交、未提交修改及反例。旧分组、完成标记、审批回合和规划预算不作为 V2 的执行依据。
4. 先在本地检查导入候选是否保留既有测试，将具体问题一起提供给 provider，再使用其原生规划能力生成一次整体计划。不再另设“是否值得修复”或“批准组件计划”的模型阶段。
5. 在同一候选和原生会话中连续实施，跨模块修复同一个根因。控制器负责 Git 提交；provider 无权修改 Git 元数据。
6. 保存实施结果及次数，在本地检查既有测试是否保留，然后冻结候选，集中执行正式测试，并同时进行独立代码审查。测试按实际收集到的节点拆分为执行批次，批次没有独立规划、依赖审批或完成状态。
7. 对审查映射的行为测试进行修复前后对照，再在无凭据、无网络的项目副本中验证原会话恢复边界。
8. 全部通过后生成绑定目标、代码、环境、测试、审查及恢复证据的验收收据。整合期间若本地/远端引擎推进，在保留候选中合并并重新验收；不会重建整份计划。
9. 只在源工作区干净且当前 generation 仍有权限时回写。恢复原会话前再次验证收据和当前项目副本；远端发布沿用操作者配置，不执行候选内的修复控制逻辑。

## 失败与中断

- 测试保留检查收集各文件的具体断言、入口和参数问题，交回同一个实施会话修正，使用相同的持久失败预算；不会第一次检查失败就将任务永久阻塞。检查阶段中断后从保存的候选继续，不重做已完成的实施。
- 本地检查允许保留旧断言的合取增强，以及可以静态核对旧场景仍存在的字面参数扩展；不以文件级断言总数替代每个测试的保护。无法证明的改写需要保留原检查并单独添加新场景。此检查不能代替正式测试、独立审查和行为对照。
- 早期 V2 的 `tests_weakened` / `tests_invalid` 阻塞在操作者明确重启时，先用新控制器复核原候选；复核通过即进入验收，保留原计划、会话和已有预算。
- 测试或审查发现明确阻塞后，停止另一侧不再需要的工作；最终通过仍要求完整测试和有效独立审查。
- 未改变的源码、环境、契约和反例可以复用独立审查。测试只有在静态依赖闭包可证明完整时才跨版本复用；动态导入、文件访问、环境/时钟依赖等不透明情况重跑。
- 进展与历史最佳已验证阻塞集合比较。问题在 A/B 之间反复出现不能不断获得新预算。
- 连续两次实施没有可验证改进，允许一次重新诊断；再连续两次无改进则停止并保留现场。
- 中断保留计划、候选和原生会话。原生会话明确不存在时只允许一次用完整保留上下文恢复，不能无限重试。
- 实施达到单次时限时，如果隔离进程已停止且源码确有修改，保存这份未验收候选并进入原有测试保留检查、集中测试、独立审查和行为对照。模型超时不表示候选通过；没有源码变化的超时、其他供应商错误及用户主动取消仍分别处理，不自动循环调用模型。旧版超时存档在明确重启后可先验收保留的修改，不重做这一段实施。
- 新的恢复反例会撤销旧验收，保留为后续必验输入，并回到原计划的实施阶段。
- guarded 模式只验证已有源码，不生成修改；off 模式不启动自主修复。

## 固定验证环境与磁盘生命周期

- 验证器和恢复探针由控制器提供，候选不能替换。Docker 镜像固定到内容 ID，环境指纹包含驱动、Docker 版本、内核、UID/GID 和资源配置。
- 测试容器使用私有工作副本、无网络、固定资源上限和 init 进程。嵌套沙箱测试有明确的验证 profile；不会挂载真实项目、provider 凭据或 Docker socket。
- provider 使用独立原生 HOME，只接收当前 provider 的配置及凭据；规划/审查挂载只读源码，实施只允许写候选。
- 工具镜像包含 `dirname`、`basename`、`rg` 等源码查找工具，并在使用前做实际可执行检查。原生输出片段保留在原生会话记录中，不逐片段同步写控制器事件日志。
- 复制前及过程中检查 Linux 和 WSL 宿主盘空间，保留至少 2 GiB 恢复空间。
- 测试副本在正常结束、失败和取消后清除。崩溃遗留只有在精确标签匹配且内核租约已释放时才回收。
- 只保留两份已展开的候选快照；历史提交和文件清单仍可重建旧版本。脏或未知快照不自动删除。
- 镜像构建目录退出即清理；镜像按内容复用。镜像登记库保留未完成事务的引用和最近两份镜像，未引用旧镜像按 14 天策略回收，不操作 Docker 数据卷。
- 原始请求、验收收据和必要恢复证据保持可追溯。旧候选仅在后续交付已证明继承其历史后，才交由既有存储维护策略回收。

## Provider 适配

| Provider | 规划 | 实施/恢复 | 独立审查 |
| --- | --- | --- | --- |
| Codex CLI | app-server 原生 Plan | 原生 thread/turn，恢复时不重复导出历史 | 独立 thread，结构化输出 |
| Claude Code | 原生 plan permission mode | 原生会话恢复和 stream-json | 独立会话，JSON schema |
| Copilot CLI | 原生 plan mode | 原生会话恢复和 JSON 事件 | 独立会话，控制器校验 JSON |
| Antigravity CLI | 原生 plan mode | accept-edits / conversation | 独立 conversation，JSON schema |

保留 `antigravity-gemini`、`antigravity-claude` 名称，它们指向 Antigravity CLI，不是 Gemini CLI。规划与独立审查使用配置的 `self_repair_review` 档位，实施使用 `self_repair` 档位。格式纠正不能改变审查的实质结论或删除阻塞证据。

本轮按用户要求只进行 Codex CLI 真实验收；其余 provider 保留适配及离线协议测试，不能将此理解为其他账号服务已验收。

## 验收记录

结果和实测限制见 `self-repair-v2-validation.json`。合成小例、跨模块命令归属例、中断恢复例以及原始 sdgp 恢复副本检查分别记录，失败的供应商初始化不计入提速成绩。75% 是性能目标，是否达到以配对实测为准，不由调用次数或理论估算替代。
