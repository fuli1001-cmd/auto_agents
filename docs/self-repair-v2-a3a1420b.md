# a3a1420b：取消验收被误报为环境故障

2026-09-15 的任务 `a3a1420b32b64d2ab509786d` 已正确接续上轮候选，没有重新规划。第一次集中验收发现 10 个运行时身份测试失败，实施会话完成了一次修正；第二次验收中这 10 个测试均已通过。

第二次独立审查提出两项候选缺陷：模块限定的继承基类未纳入测试正文保护，以及 pytest `--setup-only` 被当成可执行证明。控制器因此取消剩余测试。四个批次返回取消，其中两个取消发生在容器完成创建之前，未取得容器状态。

旧代码把“没有容器状态”统一标为基础设施错误；汇总时从失败列表排除了取消批次，却仍把它们计入基础设施错误。因此产生矛盾结果：`cancelled=true`、`infrastructure=true`、`failures=[]`，最终向用户显示 `修复受阻：[]`，没有继续处理审查意见。

修复后的行为：

- 记录进程是否启动、取消或超时的原因、原始退出码以及实际容器状态。
- 取消发生在启动前时直接返回，不启动进程；取消造成容器状态缺失时不再推断为环境故障。
- 明确的 OOM、Docker 启动错误和已经报告的测试失败仍然保留，不因同时收到取消而被忽略。
- 基础设施标志与失败列表采用同一组有效结果；即使异常验证器未提供明细，也会生成可读诊断，不输出空数组。
- 对这类旧存档，核验源码、请求、审查输入及存档摘要后，恢复已保存的拒绝意见，回到同一个实施会话。
- 之前失败的测试确实通过时计为进展。每个失败只能获得一次此类进展额度，反复切换 A/B 失败不能无限续期。

验证包括 106 项相关回归、实际 Docker 容器启动后的取消检查，以及原事务的隔离恢复回放。回放恢复了两项审查意见，保留计划、会话和实施次数，增加零次模型调用、零次重新规划；原任务和 sdgp 会话没有被修改或启动。

隔离验证记录：`.auto-agents/maintenance/a3a142-cancellation-replay.json`、`.auto-agents/maintenance/a3a142-real-docker-cancellation.json`。这些结果只验证控制器修复，不表示剩余候选缺陷已经修复或整体验收通过。
