## 已实施的调整

- 集中验收汇总普通测试失败，避免一个批次失败后把其他问题留给下一轮。
  基础设施故障、用户取消或独立审查的明确拒绝仍可以中止工作。
- 发现动态输入后立即停止无法闭合的依赖分析，不再继续遍历整个引擎。
  同机、同快照的两个抽样从约 3.94/3.54 秒降为 0.011/0.009 秒。
- 动态输入测试仍强制实际执行：相同文件状态不能约束时钟等外部状态。
  保留完整输入证明后才可缓存的原有规则，失败、强制刷新和损坏记录不得复用。
- 使用历史耗时合并已知短模块，并优先启动长批次；历史失败仍优先。
  旧清单重新编排为 136 批，4554 个用例全部保留。新代码新增的回归测试另计。
  调度记录仅影响排队和分批，不构成通过证据。
- 运行中按实时内存重新计算并发额度，独立审查结束释放内存后可增加测试槽位，
  不再受启动瞬间较小的内存额度限制到整个验收结束。
- 旧源码对照先分模块收集，再将参数化用例分片并行；收集错误、夹具错误、
  strict XPASS、源码被测试改写均不能作为成功反例。
- 超时明确归为验证基础设施问题；工作线程异常时先取消其他正在运行的检查，
  防止线程池退出等待掩盖原始错误。失败验收不会清空修复预算。
- 保存每个测试用例耗时以及包含准备阶段的总耗时，后续性能分析无需只按
  批次数猜测。缓存和调度记录的写入失败不会取代正式执行结果。

完整源码或验证策略变化仍需重新验收。批次重排与局部基准不能单独证明端到端
提速；正式验收应以最终固定源码的实际结果为准，并保留原会话隔离回放。
